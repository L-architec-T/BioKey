# Liquid Glass

> Source de vérité : `android-foundation/design-system/`. Implémentation de référence : DFlow (`ui/theme/Theme.kt`).

Moteur de verre réel (`io.github.kyant0:backdrop`), réglages et règles de mise en page.

## 5. Liquid glass engine

Real backdrop-sampling glass (not a fake blurred screenshot), via `io.github.kyant0:backdrop`:

- The screen's wallpaper `Image` is recorded **once** into a shared `LayerBackdrop`
  (`Modifier.layerBackdrop(backdrop)`, via `rememberLayerBackdrop`).
- Every `GlassCard`/glass surface on that screen samples the **same** recording through
  `Modifier.drawBackdrop(...)`, so each card shows exactly the slice of the real background behind
  it — cards don't need their own screenshot.
- `GlassCard` degrades gracefully: if `AppTheme.liquidGlassEnabled` is false or there's no
  wallpaper set, it just draws a flat `fallbackColor` box (`BgCard` by default). Glass is always
  additive polish, never a hard requirement for the UI to render.

8 sliders, each stored 0..1 in `AppTheme` and mapped to the library's real units at the call site
(`Modifier.liquidGlassCard(...)`) so the UI range stays stable even if the mapping is retuned:

| Slider | AppTheme field | Default | Maps to |
|---|---|---|---|
| Blur | `glassBlur` | 0 (apps generated by `app`: 0.03, see §5.1) | `blur((amount * 22).dp)` |
| Distortion | `glassDistortion` | 1 | `lens(refractionHeight, refractionAmount, chromaticAberration=true)` |
| Reflection | `glassReflection` | 0.3 | `Highlight.alpha` |
| Glow | `glassGlow` | 0 | outer `Shadow` (accent-colored, `BlendMode.Plus`) |
| Corner | `glassCorner` | 0 | lens `refractionHeight` = `(6 + amount * 30).dp` (bande de réfraction serrée contre le bord, 1.12.0 ; avant 12–70dp) — not the shape radius |
| Tint | `glassTint` | 0 | `onDrawSurface` rect alpha (0.15–0.55) over `BgCard` |
| Border | `glassBorder` | 0.5 | `Highlight.width` (0.5–3dp) |
| Shape radius | `glassShapeRadius` | 0.4 | card corner radius, 2–28dp (§3) |

These 8 constants are declared once (`GLASS_DEFAULT_*`) as the single source of truth for both the
DataStore read-fallback and the "RÉINITIALISER" reset target — never duplicate the numbers.

### 5.1 Saved preferences (what `app` generates)

`scripts/app.sh` patches these defaults into every generated app: **dark theme**, **liquid glass
OFF** (decided 2026-09-24), and the **accent color chosen in the script**. The glass tuning from the
user's phone (CallUp, 2026-09-21) stays preselected so turning glass on in Apparence gives it
straight away: wallpaper **`matrix`**, **blur 0.03**; the other seven sliders keep the table's
values. With glass off no wallpaper is drawn (`ScreenWallpaperBackdrop` requires glass on). The same three values live in several places that must
agree — `AppTheme` (cold-start value), `AppearancePreferences.load()` (the DataStore fallback
`MainActivity` reads on every launch) and the "RÉINITIALISER" targets in `ConfigDialog` — so change
them together, and mirror any change in `app.sh`'s "Apparence par défaut" block (which also
verifies the result and warns if a pattern stopped matching).

### 5.2 Screen layout — one backdrop per screen (mandatory)

Wrap **each screen's root** in `ScreenWallpaperBackdrop(Modifier.fillMaxSize()) { ... }` once. It
draws the wallpaper full-screen, records it into one `LayerBackdrop` and provides it through
`LocalScreenBackdrop`; every `GlassCard` inside then samples that shared recording. Rules:

- Without the wrapper, `GlassCard` falls back to drawing **its own** wallpaper crop scaled to the
  card, so every card shows the whole picture squeezed in, and the wallpaper never appears behind
  the screen. That is the "badly implemented liquid glass" look — the skeleton `app` generates used
  to have this bug and no longer does.
- Dialogs (`SliderSafeDialog`, `GlassAlertDialog`, `ConfigDialog`) sit **outside** the wrapper, after
  it — they keep the card-local fallback.
- A `Scaffold` inside the wrapper must be see-through or it hides the wallpaper:
  `containerColor = if (wallpaperBackdropActive) Color.Transparent else BgPrimary`
  (`wallpaperBackdropActive` = `AppTheme.liquidGlassEnabled && AppWallpapers.find(AppTheme.wallpaperKey) != null`,
  declared in `Theme.kt`).

### 5.3 Bottom navigation — floating glass tray

**Composant prêt à l'emploi : [`components/GlassBottomNavBar.kt`](components/GlassBottomNavBar.kt)**
(extrait de CallUp, copié automatiquement par le script `app` dans `ui/components/` de chaque
nouvelle app). Usage :

```kotlin
val tabs = listOf(NavTab("Accueil", Icons.Outlined.Home), NavTab("Réglages", Icons.Outlined.Tune))
var tab by rememberSaveable { mutableIntStateOf(0) }
ScreenWallpaperBackdrop(Modifier.fillMaxSize()) {
    Scaffold(
        containerColor = if (wallpaperBackdropActive) Color.Transparent else BgPrimary,
        bottomBar = { GlassBottomNavBar(tabs, selectedIndex = tab, onSelect = { tab = it }) },
    ) { padding -> /* contenu de l'onglet, Modifier.padding(padding) */ }
}
```

Pour une app existante : copier le fichier dans `ui/components/` en remplaçant `__PKG__` par le
segment de package. Implémentation détaillée (référence) :

The bottom bar is a `GlassCard`, like every other surface, not an opaque `NavigationBar`:

```kotlin
bottomBar = {
    GlassCard(
        modifier = Modifier.padding(start = 16.dp, end = 16.dp, top = 4.dp, bottom = 8.dp),   // never touches the screen edges
        radius = 28.dp,
        fallbackColor = BgCard,
    ) {
        NavigationBar(containerColor = Color.Transparent) {
            // selected item: icon + label in Accent, indicatorColor = Accent.copy(alpha = 0.12f)
        }
    }
}
```

- Fully rounded (28dp, the dialog radius of §3), inset 16dp left/right and 8dp from the bottom.
- Glass on: the tray refracts the wallpaper, the glass highlight is its edge. Glass off: flat
  `BgCard` — **exactly the cards' color** (never `BgSurface`, which reads as a darker, unrelated
  strip next to the cards). **No border/hairline on the tray, ever** (glass on or off).
- Selected tab uses the same wash as the "+" button and the stats pill: 12 % accent fill (the
  pill's 50 % outline is not available on `NavigationBarItem`'s indicator).

### 5.4 Wallpaper shown, liquid glass OFF — "+" button look (1.13.0)

When a wallpaper is actually drawn behind the screen but liquid glass is **off**, no surface may
stay an opaque `BgCard`/`BgPrimary` block hiding it. Every card (stats container, list rows, …) and
full-screen panel takes **the `GlassFab` look without any outline**: 12 dp blur of the screen
backdrop, 12 % `Accent` wash (the button itself keeps its 50 % `Accent` outline) — via
`Modifier.glassFabSurface(backdrop, shape, borderColor = Color.Transparent)`
(`components/GlassFab.kt`), on a background-only layer behind the content:

```kotlin
when {
    glassEnabled -> Box(Modifier.matchParentSize().liquidGlassCard(backdrop, radius, radius))
    wallpaperShown -> Box(Modifier.matchParentSize().glassFabSurface(backdrop, shape, borderColor = Color.Transparent))  // glass OFF + wallpaper
    else -> Box(Modifier.matchParentSize().background(BgCard, shape))                  // unchanged
}
```

- A transparent `borderColor` also drops `drawBackdrop`'s default edge highlight (it reads as a
  thin light rim otherwise). Menus and dialogs (sub-menus) get the same look; a dialog sits in
  its own window: its `GlassCard` records its own wallpaper crop + scrim instead of sampling the
  screen's recording.
- **Top bar**: same blur, no outline — `AppTopBar` does it itself (full-width strip,
  `RectangleShape`); a screen drawing its own header (Donova) uses the same call.
- Glass on, or no wallpaper: unchanged (slider-driven glass / flat `BgCard`).
- `backdrop` = the screen's wallpaper recording (`LocalScreenBackdrop` / the screen's own
  `LayerBackdrop`), never a layer that records the card itself.
- Only reachable in apps that draw the wallpaper with glass off — today **Donova** only
  (`wallpaperBackdropActive` = wallpaper picked). In apps generated by `app`,
  `ScreenWallpaperBackdrop` draws nothing with glass off (§5.1), so this branch never triggers.
